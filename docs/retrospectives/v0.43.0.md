# Release Retrospective: v0.43.0

**Theme:** dissolve the empirically-confirmed delivery binding constraint (the WS-4
`conflict_3way_failed → re_architect → "no plan initialized"` cascade), close the
findings the Phase-4 field re-run surfaced, and adopt **curated minimalism** — do the
least that fully satisfies the task, never skipping safety / validation / security.

**Shipped:** to `main`. PyPI/npm publish is the operator's call (recent 0.42.x were
deliberately held at PyPI v0.41.0). The in-repo gate is green: **4352 passed / 6
skipped**, `ruff check src tests` + `mypy src` exit `0`.

**Source of truth:** the two Phase-4 field re-runs
(`thoughts/investigations/autodev-stabilization/field-probes/REVALIDATION-RESULTS.md`)
— the 1st (HEAD `95ae3b2`) isolated the WS-4 root cause + surfaced F-1/F-2/F-5; the 2nd
(HEAD `569bda5`) field-validated F-5 (a hard feature probe that previously timed out in a
`.pyc`-conflict loop delivered a clean 136-line implementation) and surfaced F-6/F-7.

## 1. What shipped

- **A1/A2 — the WS-4 binding constraint.** Root cause was two compounding defects:
  `abort_failed_apply` ran a repo-wide `git clean` that wiped the main-repo `.autodev/`
  ledger mid-run (now excluded — A1), and trivial fixes hit **spurious** 3-way conflicts
  because the apply path never first attempted `git apply --3way` before consulting the
  critic (A2). The `conflict_3way_failed → re_architect → "no plan initialized"` cascade
  no longer reproduces (language-general).
- **A4/A5 — delivery + metrics.** A delivered + `APPROVED` fix now finalizes, commits, and
  exits `0` (was exiting `2`); execute-phase invocation cost is recorded as a metric.
- **B1–B3 — curated minimalism (ponytail-inspired).** A necessity-ladder ("laziness
  ladder") is injected into the architect + developer roles (B1); a **non-blocking**
  reviewer over-engineering / tech-debt advisory ledger op (B2); effort-modulated intensity
  — minimal at low effort, deeper at high/max (B3).
- **F-1–F-7 — field findings, each reproduce-first + reviewed.** Plan-repair admits a task's
  own declared files into its phase `edit_scope` (F-1); a phase-scoped non-convergence
  ceiling fails **loud** instead of churning correctives to the wall (F-2); the benchmark
  harness emits result JSON safely on timeout / non-UTF-8 output (F-3); apply-time
  edit-scope enforcement is wired (was dormant — callers passed `edit_scope=None`) with a
  `warn`-default knob + **binary-aware** diff parsing (F-4); delivered diffs are
  self-contained (`git diff --binary --full-index`) and exclude generated cruft, fixing the
  binary-`.pyc` defect that surfaced as a spurious `conflict_3way_failed` loop (F-5); the
  per-task sparse worktree includes a capped, tracked-only, scoped test-harness globset and
  skips `npm test` when there is no `package.json` (F-6); a default-off plan-phase
  wall-clock ceiling salvages the incumbent instead of an opaque external `SIGKILL` (F-7).
- **CI:** `ruff` is now a **declared** dev dependency (`ruff>=0.15.11,<0.16`) — the Lint gate
  `uv run ruff check src tests` could not spawn `ruff` on a clean runner where it was only
  on a developer's `PATH`.

## 2. What broke during this build (and was caught)

- **F-5 was misdiagnosed as genuine non-convergence.** The recurring `conflict_3way_failed`
  on hard tasks was assumed to be source-level churn; observing the actual delivered diff
  (per the observe-before-editing rule) revealed a **binary-`.pyc` diff defect** —
  `get_diff_vs_base` ran `git diff` without `--binary --full-index`, so a pytest-regenerated
  `__pycache__/*.pyc` emitted a malformed binary hunk → spurious `git apply --3way` rc=1.
  The source `.py` always applied. Editing the resolver would have been wasted work.
- **The apply-time scope gate was dormant (F-1 GATE → F-4).** Investigating F-1 surfaced
  that the execute flow's apply-time `edit_scope` enforcement was never active (callers
  passed `edit_scope=None`) and the diff parser ignored binary headers — promoted to its own
  finding (F-4) rather than silently relied upon.
- **Subagent-continuation drift.** A `SendMessage` continuation once reverted earlier work in
  the working tree; caught by observing `git` state before acting, restored via `git
  restore`, and avoided thereafter by dispatching fresh implementers.

## 4. What's NEW (failure modes introduced this release)

- **F-4 apply-time enforcement defaults to `warn`.** Promoting the default to `block`
  requires clean warn-telemetry from a real run first, and the binary rename+space header
  parse is best-effort under `block` — a malformed rename could over-block. Mitigated by the
  `task.files ∪ files_new ∪ extended_scope` union (prevents false positives) + empty-scope
  no-op (corrective tasks with empty `files` aren't blocked).
- **F-7 wall budget is default-off.** It converts an opaque `SIGKILL` into an attributable
  salvage, but the LATENCY that triggers it is environmental — leaving it on by default
  could truncate a legitimately slow tournament. Re-measure under normal latency first.
- **F-6 sparse-cone globset is capped.** A huge repo with an unusual harness layout could
  exceed the header cap and bail (degrade-loud); the scan is root + the task's ancestor dirs
  only (never repo-wide) to stay bounded.

## 5. What's the NEXT layer of failure? (v1.0 input)

- **A clean field sweep under NORMAL latency.** This session's two re-runs ran with
  abnormally high claude latency (~40–80s/call); P5 (plan) and P6 (50k execute) hit the
  40-min per-command caps partly because of it. v0.43.0 is a stabilization RC, **not** v1.0
  — only 2/5 probes delivered. The bar for v1.0 is P1/P2/P4/P6 deliver-or-fail-loud cleanly
  under representative latency.
- **Promote F-4 `warn` → `block`.** Only after warn-telemetry from a real run is clean, and
  after tightening the binary rename+space diff parse so `block` can't over-block a valid
  rename.
- **50k convergence within budget.** P6 ran with `0` `.pyc` errors but did not converge in
  the execute budget on genuine bounded churn — separate the latency confound from a real
  convergence ceiling before tuning budgets.
- **P3 (Rust) is unexercised.** Deferred both re-runs (no `cargo` on the box); the
  language-general claim for A1/A2/F-5 is unproven on the Rust path.
- **F-7 default decision.** Decide whether to enable the plan-phase wall budget by default
  once normal-latency timings establish a safe ceiling that won't truncate legitimate work.

## 6. Process / discipline notes

- **Observe-before-editing paid off twice.** It caught the F-5 misdiagnosis (the defect was
  in the diff command, not the resolver) and the subagent working-tree revert. Outputs don't
  lie; code might.
- **RED-on-HEAD per fix.** Every finding shipped with a reproduce-first test whose
  deliberately-broken control turns red on the unfixed HEAD — the engagement discipline the
  v0.41.0/v0.42.0 "ships green but inert" failure class kept violating.
- **Don't claim the field bar prematurely.** The honest verdict is that v0.43.0 stabilizes
  the delivery binding constraint and clears the binary-`.pyc` blocker, but does NOT clear a
  clean field sweep — that gate is explicitly deferred to a normal-latency re-run.
