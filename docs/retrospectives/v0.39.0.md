# v0.39.0 retrospective — Tier J

Huge-repo-native. The prior dogfood run on a 358k-file, Git-LFS, unbuildable
engine repo only completed after a stack of manual workarounds (disabling the
target's MCP servers, bumping probe retries, hand-capping parallelism, forcing
the unrunnable-tests soft-pass, raising reviewer/ceiling turn budgets, an
editable install). Tier J folds every one of those into auto-applied,
capacity-aware behaviour so a huge/unbuildable repo runs with **zero
`.autodev/config.json` edits and zero env vars**. Six distinct gaps were each
surfaced by a from-scratch run, root-caused, fixed, and re-validated live.

Every change is additive, idempotent, a no-op on small repos, and gated by the
existing `huge_repo_overrides_disabled` escape hatch.

## 1. What shipped

- **J1 — Parallel index build + run cost/time telemetry.** Full index build is
  ~45s vs ~99 min serial (forkserver pool + bulk-load FTS rebuild, landed
  pre-tier and now defaulted sync on huge repos). Run cost is now recoverable:
  a transparent `CostRecordingAdapter` emits a per-invocation `invocation_cost`
  ledger op for **every** adapter call (main path *and* tournament judges/
  developers — the in-memory `GuardrailEnforcer.plan_cost_usd` budget cap only
  sees the main path), and `autodev plan`/`execute` append a
  `{phase, cost_usd, elapsed_s, tasks, ts}` row to `.autodev/run-summary.jsonl`
  plus a printed `Run cost: $X · wall Ns` line.
- **J2 — Auto-applied huge-repo profile + robust preflight probe.**
  `apply_huge_repo_profile` (runtime/ephemeral, never written to disk)
  auto-enables `worktree_sparse_checkout_enabled` and
  `treat_unrunnable_tests_as_no_tests` on a huge **and** unbuildable repo
  (new C++/CMake detection + `is_repo_unbuildable`). Turn ceilings are now
  configurable (`BudgetEscalationConfig`) and huge-scaled; non-task roles
  (reviewer, etc.) finally scale on huge repos. The PONG probe uses a fast
  model (`adapters.probe_model="haiku"`, ~7-8s vs ~9-11s) and the unbound
  detect-time timeout is 10→20s, so the probe stops flaking on slow cold-starts
  and the target repo's MCP servers can stay enabled (spawned agents are
  isolated via `--setting-sources user --strict-mcp-config`).
- **J3 — Sparse worktrees (all paths) + stale-lock cleanup.** Both the
  execute-phase (`create_per_task`) and impl-tournament worktree paths now
  create **sparse** worktrees (cone from the task's files) with
  `worktree_huge_create_timeout_s`, eliminating the ~62 MB LFS phantom diffs
  that blew the diff-size guardrail and the 60s `git worktree add` timeouts.
  `clear_stale_index_lock` defensively clears a stale main-repo
  `.git/index.lock` (unowned + aged) before `git apply`, so a killed/contended
  git op no longer cascades into `rc=128` apply failures.
- **J4 — Accept approved-but-turn-exhausted research tasks.** A research/
  empty-diff task whose reviewer-APPROVED empty diff is on record is accepted
  on turn-exhaustion instead of stalling at a `user_decision_required`
  soft-block (strictly gated: turn-exhaustion subtype + APPROVED verdict +
  empty in-hand diff; semantic failures still block).
- **J5 — `.autodev/` containment.** A developer diff confined entirely to
  AutoDev's own `.autodev/` directory is rejected as invalid task output
  *before* the reviewer runs and routed to retry/escalate — it can never reach
  `complete` (new `containment_violation_autodev_paths` op).
- **J6 — Phase-review corrective scoping.** `drift_verifier` parser
  diagnostics (`drift_verifier:` / `drift_convergence_failure:` prefixed) are
  partitioned out of corrective generation (`partition_drift_findings`), so the
  phase review stops spawning "fix AutoDev's own drift_verifier" meta-
  correctives and stays on the target bug. The verdict still drives control
  flow; only the leaked diagnostic text is filtered (fail-open).

## 2. What changed

New: `orchestrator/huge_repo_profile.py`, `orchestrator/cost_recorder.py`,
`state/run_summary.py`. Touched: `config/schema.py` (probe_model,
suppress_target_repo_config, BudgetEscalationConfig, new huge_repo_multiplier
keys, reviewer 1.5→2.5), `adapters/{claude_code,detect,git_utils}.py`,
`orchestrator/{__init__,execute_phase,worktree,huge_repo_overrides,plan_phase,
drift_verifier,phase_review_runner,impl_tournament_runner,*tournament_runner}.py`,
`qa/detect.py`, `state/ledger.py` (new audit ops: `invocation_cost`,
`accepted_approved_on_exhaustion`, `containment_violation_autodev_paths`,
`auto_soft_pass_enabled`, `task_under_decomposed`), `agents/prompts/architect.md`.

New default flip: `adapters.suppress_target_repo_config=True` (a soft breaking
change — spawned headless agents no longer load the target repo's project/local
settings or MCP, but `CLAUDE.md` still loads).

## 3. Verification

- ~3427 unit tests green; `ci/release_preflight_greps.sh v0.39` locks the 17
  load-bearing integration anchors for this tier.
- **End-to-end, fully autonomous** `init → plan → execute` on the real
  358k-file repo (UUM-136411 — GLES GPU-profiling timer-query + debug-group
  depth lifecycle across context switches) **completed cleanly**: 8/9 tasks
  complete (1 skipped), **8 commits** landing the full fix (14 files,
  +1866/−49: per-context timer-query state, a per-context deferred-cleanup
  queue, per-context debug-group depth, a thread-safety audit, ~1357 lines of
  new tests). **Zero gap recurrences, zero corrective contamination, zero
  blocked tasks**, zero manual config tweaks, target bug-details preserved.
- Cost **$31.50** (plan $9.92 / execute $21.58), wall ~7.1h, index build 45s.

## 4. Next layer of failure

- **Pooled-worktree path** (`worktree_pool_enabled`, default off) still builds
  its `WorktreeManager` non-huge — it would reintroduce the J3 non-sparse +
  60s-timeout failure on huge repos if pooling is enabled. Route it through the
  shared huge-safe creation before turning pooling on for huge repos.
- **`plan_cost_usd` budget cap undercounts.** The enforcer's in-memory cost cap
  only sees main-path invocations, so tournament spend (the majority) escapes
  the `cost_budget_usd_per_plan` guardrail. The new ledger-based total is
  authoritative for reporting, but the *cap* should sum tournament cost too.
- **Plan-phase cost variance.** Observed $3 / $9.92 / $13.94 for 5–15-task
  plans on the same bug; the plan tournament + decomposition can balloon. Worth
  a cost/round cap or a tighter convergence signal.
- **Drift-verifier critic prompt-compliance.** J6 stops the *leak* of the
  critic's non-standard verdict text into correctives, but the root cause is
  that `critic_drift_verifier.md` emits `VERDICT: PASS/PARTIAL/FAIL` while the
  parser mandates `APPROVED|NEEDS_REVISION`. Aligning the critic's vocabulary
  would remove the malformed-verdict path entirely.
- **Corrective-context scoping is partial.** J5 (containment guard) + J6
  (drift-finding partition) stop the two observed leaks, but the architect-
  consult evidence builder could still surface other AutoDev-internal artifacts
  on a different failure shape. A general "only target-repo evidence enters
  agent prompts" invariant would close the class.
- **Research tasks remain budget-fragile.** J4 accepts an approved empty diff
  on exhaustion, but a research task that exhausts turns *before* producing any
  reviewable artifact still depends on escalation/skip; finer scoping or an
  explicit "investigation" task kind with a different budget envelope is the
  next lever.
