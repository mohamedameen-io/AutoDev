# Release Retrospective: v0.42.0

**Date:** 2026-06-15
**Release tag:** v0.42.0 (push to main; **NO PyPI publish** — operator triggers publish)
**Postmortem author:** AutoDev maintainers
**Triggering event:** The Run-4 benchmark (v0.41.0 vs PR #200, Synaptix Mistral-429) confirmed the
execute-layer fixes landed a coherent fix autonomously, but exposed the two marquee phases (Intake

> This release ships in one cut: the Run-4 point-fixes (C1–C6) **and** the Universal Blocker Resolver
> (ADR-0047). The point-fixes double as the resolver's deterministic fast-path primitives; the resolver
> is the catch-all above them.

## 4. What's NEW (failure modes introduced this release)

- **Resolver cost amplification.** Active recovery re-enables tasks (re-arming the retry budget), so a
  persistently-failing task now consumes up to `max_cycles_per_blocker` extra recovery cycles before
  blocking. Bounded by the per-blocker budget + the in-memory guard, but it is a real cost increase on
  genuinely-stuck tasks. Mitigation: `fast_path_only_on_known=True` keeps cost ≈ 0 for recognized,
  already-recoverable cases.
- **Resolver scoped OFF in the test suite.** An autouse conftest fixture sets `AUTODEV_RESOLVER_DISABLED=1`
  for every test except those marked `@pytest.mark.resolver_enabled`. This gives legacy tests exact
  pre-resolver behavior, but means the general suite does **not** exercise the resolver-enabled execute
  paths end-to-end — only the dedicated wiring tests + `test_blocker_resolver.py` do. A real
  resolver↔execute regression could hide between them.

## 5. What's the NEXT layer of failure? (v0.43.0+ input)

1. **The resolver is field-untested (highest priority).** Every assertion in §3 is from unit tests;
   no live run has fired the resolver against a real blocker yet. *Falsifiable signal:* a Run-5
   benchmark with a `resolution_chosen` ledger op that demonstrably re-enables the workflow (gate (e)).
   Until then, "the resolver makes AutoDev autonomous on unanticipated failures" is a hypothesis.
2. **Conflict / worktree-apply / infra-circuit sites are observability-deferred.** These terminal sites
   return `bool` (don't fit the recover-and-return-Task pattern) or are intentional phase-wide
   quarantines, so v0.42 does NOT route them through the resolver. *Falsifiable signal:* a real run that
   dead-ends at a 3-way-merge conflict with no `blocker_escalated` op — the resolver was blind to it.
3. **Active recovery vs. the existing escalation ladder may double-recover.** The soft-blocker site is
   itself the terminal rung of the architect-consult/critic ladder; the resolver then recovers again.
   *Falsifiable signal:* a task that the ladder soft-blocked, the resolver retried, and that still
   failed — wasted cycles with no new information. Consider making the resolver strictly *after* and
   *distinct from* the ladder, not stacked on it.
4. **The deterministic ladder's action choices are hand-tuned, not learned.** `deterministic_action`
   maps each class to a fixed rung order. *Falsifiable signal:* a class where the chosen first rung is
   systematically wrong (e.g. `retry_with_changes` on a deterministic-bug failure that retry can never
   fix). Knowledge-store feedback could re-rank rungs per class over time.
5. **Scope-off-in-tests hides integration drift.** See §4. A periodic `resolver_enabled` integration
   sweep (run the execute suite with the resolver ON, triage the shifts) would catch regressions the
   default suite cannot.

## 6. Process / discipline notes

- **Verify-the-output discipline paid off.** The "hang at 44%" was diagnosed by checking the output
  file's mtime/byte-growth (slow vs. hung) and reasoning from the fake-ledger loop, not by guessing.
- **Per-cluster TDD beat a global tests-first phase.** Giving each fan-out agent ownership of both its
  impl and its tests (disjoint files) avoided cross-agent contention and produced 89 green tests with
  no merge conflicts.
- **The fail-safe invariant is the load-bearing design choice.** Every chokepoint insert is purely
  additive: resolver disabled/erroring/declining ⇒ `None` ⇒ exact legacy block. That invariant is what
  let a 17-site change to a 6,500-line file land without regressing 3,800 tests.
- **A repo-invariant test caught a real omission** (the autonomy clause) that 53 targeted tests missed —
  keep the cross-cutting lint tests.
