# v0.38.0 retrospective — Tier I

Convergence polish. Closes the four named "next layer of failure"
items from the v0.37.0 retrospective and bundles the implementation-
agent housekeeping deferrals into a single coherent release.

## 1. What shipped

- **I1** (GuardrailEnforcer wiring + huge-repo polish):
  `src/guardrails/enforcer.py` constructor now takes `cwd` and
  `parent_cfg` and resolves effective `max_duration_s_per_task` /
  `max_diff_bytes` once at init via the H5
  `resolve_huge_repo_value` resolver. Closes the H5 wiring gap —
  those caps now actually scale on huge repos. New sibling helper
  `is_huge_repo_with_ttl` in `orchestrator/repo_size.py` for long-
  lived sessions (HK11). New `huge_cpp_lang_threshold` config knob
  (default 0.80) replaces the hard-coded constant in
  `hallucination_guard` (HK12). End-to-end test synthesises 5001
  `.cpp` files on disk and asserts multiplied cap resolution (HK13).
- **I2** (bulk-resolve UX + capped-phase visibility):
  `autodev requeue --capped-phases` selects all blocked tasks in
  phases with `review_status="capped"`. `_select_task_ids` extended
  to return `(runnable, unknown, matched_capped_phases)` so the
  audit op records the phase set the flag matched even when the
  runnable list is empty after the idempotency filter. `autodev
  status --blocked` renders a top-of-panel "Capped phases" Rich
  table with per-phase lifetime `corrective_cap_reached` counts,
  scope breakdown (phase|plan from I3), and the verbatim recovery
  command. Three new status helpers
  (`_count_ops_by_name`, `_collect_corrective_cap_scope_by_phase`,
  `_render_capped_phases_panel`) follow the v0.36 F3 ledger-walk
  pattern. New audit-only `requeue.capped_phases_selected` ledger op.
- **I3** (plan-global corrective ceiling + skip-round counter):
  New `max_corrective_tasks_per_plan` config knob (default 24).
  `plan_manager.append_corrective_tasks` checks plan-scope budget
  FIRST then per-phase budget; both checks emit the existing
  `corrective_cap_reached` op with a new `scope: "plan"|"phase"`
  field. New `Phase.metadata` field (turned out to not exist
  previously — only `Plan.metadata` did) is the substrate for the
  HK5 skip-loop counter. `update_phase_meta` gains a `metadata`
  shallow-merge kwarg; ledger replay merges so counters survive
  replay. Skip-counter increments on `skip_corrective_round` at
  both call sites; resets on successful corrective injection. At
  threshold 3: warning + new `skip_corrective_loop_detected` audit
  op. No auto-soft-block in v0.38 — collect data first.
- **I4** (H3 exponential backoff + auto-reset + parallel-pool
  hygiene + typed halt): `InfraFailureCircuitBreaker` gains
  `record_test_success`, `next_backoff_s_for_test_diag`, and
  `test_diag_budget_exhausted`. The H3 trip site replaces
  hard-halt-on-3rd with an exponential-backoff loop (5s, 10s, 20s,
  ..., 120s cap; raises only when cumulative budget ≥ 600s).
  Auto-reset clears the failure deque after 3 successful test runs
  in a 900s window. `record_test_success` is fed from the
  `diagnosis="ok"` path. `InfrastructureCircuitOpenError` gains a
  keyword-only `halted_task_id` attribute (HK7) — both raise sites
  populate it; `_halt_for_auth_failed` prefers it over the existing
  plan-walk lookup. Both parallel-pool drain blocks switched to
  bounded `asyncio.wait(timeout=parallel_pool_drain_timeout_s)` +
  force-`gather` on stragglers (HK6) — the v0.37.0 H3 integration
  test that took ~30s on teardown now completes in ~0.3s (~100x
  speedup).
- **I5** (forensics + evidence polish bundle): six housekeeping
  items the implementation agents flagged, shipped together. **HK1
  (soft breaking)**: rename `"coder"` → `"developer"` in 5 user-
  facing surfaces; pydantic `@model_validator(mode="after")`
  migration shim accepts legacy `"coder"`, remaps, and emits a
  one-shot `DeprecationWarning`. **HK2**: head+tail truncation for
  `"developer"` evidence bodies in `_build_recent_evidence_block`
  (reviewer/test kinds keep tail-only). **HK3**: architect-consult
  prompt envelope dump to `.autodev/debug/architect_consult-
  {task_id}-{unix_ms}.json` via new `_dump_architect_consult_envelope`
  helper (mirrors `_dump_empty_context`). **HK8**: multiplexer
  diagnostic warning when `TMUX`/`STY` is present and trigger
  context fires (info-only). **HK9**: explicit `_CURSOR_ENV_ALLOWLIST`
  replaces the broad `startswith("CURSOR_")` heuristic; new
  `cursor_trigger_env_extra` config knob. **HK10**: `get_adapter`
  now returns `tuple[PlatformAdapter, selection_meta]`; new
  `adapter_selected` audit-only ledger op fires from each CLI entry
  after orchestrator construction. `_classify_selection_source`
  classifies five sources (`preferred`, `trigger_context`, `env`,
  `fitness`, `fallback`).

## 2. What changed

Matches the v0.38.0 CHANGELOG entry verbatim. Two soft breaking
changes called out:

- `recent_evidence_include_kinds` value `"coder"` → `"developer"`.
  Migration shim in place; removal scheduled for v0.39.0.
- `get_adapter()` return type widened from `PlatformAdapter` to
  `tuple[PlatformAdapter, dict]`. All internal callers updated;
  downstream plugins need a one-line change.

Schema changes:

- `Phase.metadata: dict[str, Any] = {}` (new field).
- `Phase.review_status` Literal unchanged (`"capped"` was added in v0.37).
- New ledger ops: `corrective_cap_reached` (extended payload with
  `scope`), `skip_corrective_loop_detected`, `adapter_selected`,
  `requeue.capped_phases_selected`.

## 4. Next layer of failure

The six things we deliberately did not solve in v0.38 — surfaced
here because they are the highest-leverage follow-ups:

1. **`huge_repo_multipliers["max_corrective_tasks_per_plan"]` not
   wired through the H5 resolver yet.** The dict entry exists but
   the orchestrator reads `plan_cap` via plain `getattr`. The
   per-phase cap goes through the resolver. v0.39 should wire the
   plan-cap through `apply_and_log_huge_repo_value` so the
   `huge_repo_multiplier_applied` op fires for both knobs.
2. **`get_adapter` tuple return is a real breaking change for any
   downstream caller outside `src/`.** All 8 internal test mocks
   were updated, but operators with thin wrappers will get
   `TypeError: cannot unpack non-iterable ClaudeCodeAdapter` until
   they update. The CHANGELOG calls this out but a one-shot loud
   warning at orchestrator startup would help.
3. **HK1 migration shim's `DeprecationWarning` fires at config-load
   time only.** In non-interactive runs the warning is easy to
   miss. v0.39 could add a one-shot loud warning during orchestrator
   startup when the operator's config originally contained `"coder"`.
4. **`_classify_selection_source` cannot distinguish `fitness` from
   `fallback` without re-running the probe.** When
   `AUTODEV_LANG_WEIGHT > 0` AND both adapters healthcheck, the
   ledger op reports `source="fallback"` (conservative) even though
   the structured log says `source="fitness"`. Small forensic gap;
   v0.39 should plumb the source out of `detect_platform` directly.
5. **Capped-phase panel shows lifetime totals.** On long-running
   plans this conflates today's fires with ancient history.
   Consider a recency window or last-N-runs filter in v0.39.
6. **Skip-loop counter resets on successful corrective INJECTION,
   not COMPLETION.** A stronger signal would be "the corrective
   tasks themselves succeeded." v0.39 should move the reset to
   the corrective-tasks-completed transition.
