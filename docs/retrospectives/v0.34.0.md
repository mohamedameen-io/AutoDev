# Release Retrospective: v0.34.0

**Date:** 2026-05-16
**Release tag:** v0.34.0
**Postmortem author:** AutoDev maintainers
**Triggering event:** Execute-phase unblock (Tier B of the v0.32.0 retrospective). v0.33 cleared the plan-phase blocker; the next live run on a large macro-heavy C/C++ codebase surfaced three coupled execute-phase failures (hallucination-guard false positives on engine macros, sparse-checkout worktrees missing sibling headers needed for symbol resolution, drift-verifier looping on a near-identical corrective patch).

## Summary
v0.34.0 closes Tier B of the v0.32.0 retrospective by allowing the hallucination guard to skip a per-language allowlist of well-known macros, downgrading unresolved-symbol findings to warnings in sparse-checkout worktrees, including sibling C/C++ headers in those sparse worktrees automatically, and adding an explicit convergence-failure exit to the drift verifier so a corrective patch that is ≥90% identical to the prior one routes to escalation instead of restarting the loop.

## 1. What shipped
- B1 (hallucination allowlist + sparse-mode downgrade): **landed** — `HALLUCINATION_ALLOWLISTS` dict + `_downgrade_in_sparse` helper added to `src/qa/hallucination_guard.py`; `run_hallucination_guard` accepts `allowlist`, `sparse_mode`, `task_id`; the orchestrator's QA gate at `src/orchestrator/execute_phase.py` selects the allowlist by the cached dominant language and derives sparse mode from `worktree_sparse_checkout_enabled` ∧ huge-repo mode.
- B2 (sparse-checkout sibling-header inclusion): **landed** — `_sibling_header_paths` helper in `src/orchestrator/worktree.py`; `create_per_task` unions the additions into the sparse pattern list under cap `WORKTREE_HEADER_EXPANSION_CAP=500`; new field `include_headers_for_sparse: bool = True`.
- B3 (drift-verifier convergence exit): **landed** — `_patch_similarity` helper in `src/orchestrator/drift_verifier.py`; `DriftVerdict.convergence_failure: bool = False` (additive); `run_drift_verifier` accepts `prior_corrective_diff` and `attempt`; the phase-review caller stashes prior diffs in per-phase memos on the orchestrator so consecutive cycles can compare.

## 2. What changed
Matches the v0.34.0 CHANGELOG entry:
- Hallucination guard now consults a per-language allowlist and downgrades sparse-worktree findings to warnings (`unresolved_symbol`).
- Sparse-checkout worktrees union sibling C/C++ headers in the same directory as edited source files (cap 500 added paths).
- Drift-verifier exits with `convergence_failure=True` when consecutive corrective diffs are ≥90% identical, routed through the existing phase-review-decision path.
- New ledger ops `sparse_worktree_expanded`, `drift_convergence_failure`. Hallucination downgrades surface via a structured `hallucination_finding_downgraded` log line.

## 4. What's NEW
- **Caused by the fix itself:** the allowlist is configured at module level and is loosened (not narrowed) by every entry it ships with. A genuinely hallucinated call to one of the allowlisted symbols on a project that has redefined the macro to a no-op now passes the gate silently.
- **Below the most-urgent layer at the prior retrospective time:** Tier C (knowledge-base hygiene — soft-flag quarantine, critic-evidence gate, promotion + decay) is now the head of the queue. v0.34 closes the execute-phase loop; v0.35 attacks the knowledge entries that survive past their usefulness.

## 5. What's the NEXT layer of failure?
**REQUIRED SECTION.** Speculate explicitly about what will surface AFTER the v0.34.0 fix ships. Input to v0.35.0 planning. At least three candidates.

- **Candidate 1:** The hallucination allowlist hides a real hallucination on a codebase that has redefined one of the shipped allowlist symbols. Severity: Medium. Why we suspect: the allowlist is global and string-keyed; a project that re-purposes `Assert` or `UNUSED` to mean something different will silently lose the guard for that symbol. Falsifiable signal: a build / test gate failure downstream that references one of the allowlist symbols, with `hallucination_finding_downgraded reason=allowlist` for the same `file`/`symbol` in the same run's log.
- **Candidate 2:** Sparse-header expansion balloons on dense include trees and either trips the 500-path cap (silently dropping all expansion for that task) or — worse — clears the cap by a single path and materializes thousands of files. Severity: Medium. Why we suspect: header directories on engine codebases often hold 200-2000 sibling headers per leaf directory; the cap was chosen conservatively but with limited data. Falsifiable signal: ratio of `worktree.sparse_header_expansion.capped` warnings to total sparse-worktree creates exceeds 10% in a real run, OR a sparse worktree's disk usage exceeds the configured `worktree_huge_pool_size` ceiling.
- **Candidate 3:** Drift-convergence threshold of 0.90 is either too lenient (real fixes that touch the same N lines trip it) or too strict (a stuck loop sneaks through with similarity 0.89). Severity: Low. Why we suspect: the similarity metric is unweighted Jaccard over the line set, so cosmetic re-indents are counted as new content. Falsifiable signal: post-run audit of last 50 phase reviews with at least one corrective cycle — count the ratio of `drift_convergence_failure` exits vs. ground-truth "the loop actually was making progress" (operator-judged). Expect 5–15% convergence exits in steady state; >25% or <2% suggests miscalibration.

## 6. Process / discipline notes
- The drift-verifier convergence threshold is currently a constant in `src/orchestrator/drift_verifier.py` (`_CONVERGENCE_SIMILARITY_THRESHOLD = 0.90`). v0.35 should move it to a config field once enough live runs exist to inform a default.
- The hallucination allowlist is module-level today; the docstring promises a config-driven extension path in a future release. That config plumb is queued for v0.35 alongside the knowledge-hygiene work.
