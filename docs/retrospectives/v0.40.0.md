# v0.40.0 retrospective — Framing/Altitude Phase (ADR-0044)

AutoDev systematically under-reached: it shipped localized patches when an
architectural change was warranted and — the deeper problem — never *posed* the
patch-vs-architecture decision at all. v0.40.0 inserts a framing/altitude phase between
exploration and planning that poses that decision explicitly and can select the
architectural option when warranted, while staying conservative by default.

Motivating field evidence: on a Mistral-429 bug AutoDev shipped a tool-observation trim
(PR #201); a human chose control/data-plane separation (PR #200, "the realized failure
of this design"). AutoDev's own dissenting plan-judge flagged the band-aid but had no
alternative strategy to vote for. The framing phase gives it one.

## 1. What shipped

- **Hybrid classifier.** Deterministic structural signals (recurrence-at-seam,
  boundary-repeatedly-touched) seed one conservative LLM call that classifies the defect
  `local_defect` vs `realized_design_failure`. Prior is `local_defect`; the flip requires
  `confidence >= 0.7` **and** at least one structural signal (`require_structural_signal`).
- **Altitude-diverse generation + selection.** On the design path, one folded call emits
  2–3 altitude-diverse `SolutionApproach`es; an `altitude_judge` Borda panel selects one
  on the rubric "eliminate vs. bound the failure class", with all five minimality levers
  suspended *scoped to that step only* (they revert for the downstream plan tournament).
- **Architect coupling.** The chosen altitude threads into the architect, which is told
  to implement THAT strategy at THAT altitude — minimality resumes for *implementation*.
- **On by default**, fail-safe (degrades to a single `local_patch`, never blocks
  planning), deterministic-on-resume (re-reads `plan-framing` evidence, zero extra LLM
  calls), with a kill-switch (`framing.enabled=false` / `AUTODEV_FRAMING_DISABLED=1`).
- Surfaced in `autodev status`; audited via `FramingEvidence` + two ledger ops
  (`framing_classified`, `framing_strategy_chosen`).

## 2. What changed

New modules `src/orchestrator/framing_phase.py` + `framing_signals.py`, prompts
`src/agents/prompts/{framing,altitude_judge}.md`, wired into `run_plan_phase`
(flag-guarded, fail-safe). New boundary models `SolutionApproach` / `FramingEvidence`,
`FramingPhaseConfig`, two `LedgerOp`s, `denylist_roles` additions, and the architect
`FRAMING PHASE COUPLING` note. The `framing` / `altitude_judge` roles dispatch via the
specialist path (`load_prompt` → `AgentInvocation` → adapter), never the registry, so
they need no `REQUIRED_AGENT_ROLES` entry.

Post-merge fix folded into this release: the lexical `hypothesis_is_a_trim` scrutiny
signal moved from substring to word-boundary matching (it had matched "cut" inside
"exeCUTing"); scrutiny-only, so no gate-behavior change.

## 3. Verification

- Two merge gates. Gate 1 (#201/#200 replay on the vendored `synaptix_core_bug.md`)
  surfaces both altitudes and selects the `design_fix`; Gate 2 (conservatism corpus)
  holds every known-local bug at `local_defect`, single `local_patch`, zero panel calls.
- Determinism: byte-identical `FramingEvidence` from `StubAdapter`, zero extra LLM calls
  on resume, identical panel shuffle from the same `spec_hash`.
- Full suite green (3506 passed). Live smoke against the real Synaptix bug with the real
  Claude adapter: the phase posed the decision and challenged the hypothesis (it
  identified the AgentExecutor's per-step sequential completions as the systematic cause)
  and — with no recurrence history and the model's own sub-0.7 confidence —
  conservatively returned `local_defect`, demonstrating the anti-over-reach guardrail.

## 4. Next layer of failure

- The classifier flips to the design path only with a structural recurrence signal or
  high model confidence; on a fresh non-git target with a sparse bug report it stays
  local. The next failure mode is a *true* realized-design-failure that lacks recurrence
  history and reads as locally-fixable — the phase will under-reach there. Mitigations:
  richer explorer/domain_expert context feeding the classifier, and promoting confirmed
  design-failure framings into the knowledge tier (currently denylisted to keep them out
  of the anti-bloat cohort).
- `architect_b` (wired-but-unused) and `re_architect` (execute-only) now overlap the
  framing phase's structural-rethink role; whether to retire them is a later question.
- The conservatism gate is tuned on a single threshold (`design_smell_threshold=0.7`)
  plus a binary structural/non-structural split. The next failure is mis-calibration: a
  bar too high under-reaches, too low invites the over-engineering the ADR guards against.
  The ADR's N=20-run review is the intended correction, but the calibration is currently
  unmeasured on real workloads.
- The design-failure path costs four LLM calls (one classifier + a three-judge panel)
  versus the one-call common case. The next failure is cost: a noisy classifier that
  flips too often turns +1 into +4 per plan. The `invocation_cost` ledger op records the
  spend, but there is no budget/alert tie-in yet, so a cost regression would surface only
  in post-hoc analysis.
