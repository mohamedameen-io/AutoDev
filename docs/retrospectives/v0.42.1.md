- **F4 — diagnosis.** Structured `files_referenced` + enriched spec into the diagnostician;

## 4. What's NEW (failure modes introduced this release)
- **`block_task` recovered-path semantics.** With the resolver ON, a recovered (re-enabled)
  task flows back where code previously assumed "blocked". The risky sites (worker
  cascade-block, soft-blocker handoff, conflict re-fetch) were hand-audited to skip the
  block-only forensics on recovery; resolver-OFF preserves exact legacy behavior. UNTESTED
  surface: the resolver-ON recovered path at each of the 20 sites individually (only the
  invariant + a few representative sites are covered).
- **`--allowed-tools ""` is field-untested.** The unit test pins command construction; whether
  the live Claude CLI treats an empty allow-list as "no tools" vs "ignored" is verified only
  by Run-6.
- **Autonomous `gh` discovery can match the wrong issue.** Mitigated by a token-overlap match
  guard (≥2) + logged chosen issue + degrade-to-repo-only on low confidence; the threshold is
  a heuristic that Run-6 will stress.
- **F1b degrade enforcement is a per-module presence check** (weaker than the block AST gate):
  it asserts `record_phase_degrade(` appears in each degrade-capable phase, not that every
  degrade path calls it. A new unreachable degrade branch could still skip it.

## 5. What's the NEXT layer of failure? (v0.43.0+ input)
1. **Resolver-ON recovered-path correctness at scale.** The invariant proves *a* breadcrumb
   precedes every block, but not that each of the 20 sites' recovered path is behaviorally
   correct under the resolver. Candidate: a resolver-enabled execute-phase integration matrix
   (one terminal failure per site → assert correct re-enable/continue), not just chokepoint tests.
2. **Strengthen F1b to match F1a.** Replace the degrade presence-check with a real
   control-flow/AST gate: every `except`-block that returns a degraded outcome must call
   `record_phase_degrade` on that path.
3. **Gather quality, not just activation.** Repo/github now activate, but the *single* gather
   agent dispatch can still return nothing under rate-limiting (the deeper Run-5 cause). Candidate:
   per-source dispatch + a "gather produced N facts" assertion + retry/backoff on the enricher.
4. **Diagnosis is still model-dependent.** The prompt now mandates a loop, but a weak model can
   still emit a vacuous `LOOP_METHOD`. Candidate: a post-parse quality gate (reject a loop with
   no command + none-fidelity + no cause) that triggers one targeted re-ask.
5. **`critic_t` turn budget.** Left at 6 (bounded input is the real fix). If Run-6 still shows
   exhaustion, lower it now that input is bounded — but only with a field signal.

## 6. Process / discipline notes
- **The enforcement test is the durable win.** F1d makes "resolver fired 0×" impossible to
  re-introduce silently — the guarantee lives in CI, not reviewer vigilance. This is the
  generalizable answer to the v0.41.0/v0.42.0 "ships green but inert" failure class.
- **The meta-test matters.** `test_invariant_catches_a_direct_silent_block` proves the
  no-silent-dead-end assertion is non-vacuous — a green gate that can't fail is the trap we
  kept falling into.
- **Parallel disjoint fan-out worked** (F2a/F2b/F3/F4 implemented concurrently by single-owner
  agents); the contended `execute_phase.py`/`plan_phase.py` were a serial single-owner phase.
- **Resolver-OFF-by-default in tests** (conftest) let a large block-site refactor land with zero
  behavior change in the legacy suite — the right call, but it means the resolver-ON path needs
  its own dedicated coverage (see §5.1).
