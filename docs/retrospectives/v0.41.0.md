# Release Retrospective: v0.41.0

**Date:** 2026-06-15
**Release tag:** v0.41.0
**Postmortem author:** Mohamed Ameen
**Triggering event:** Run-3 of the Synaptix Mistral-429 benchmark — AutoDev's *intelligence* layer (intake-enriched spec → framing at 0.85 → right-sized design-altitude plan) was strong, but its *delivery* layer could not land a complete, coherent fix. Four execute-layer bugs caused the failure; two new front-of-pipeline phases close the remaining gaps.

> This release ships in one cut: 4 execute-layer fixes + the Intake phase (ADR-0045) + the Diagnosis phase (ADR-0046). Both new phases are on by default, flag-guarded, and fail-safe (never block planning).

## 1. What shipped

- **Phase 0 — Foundation: landed.** Additive shared models/config: `SpecGaps`, `GatheredFact`, `ClarifyingQuestion/Answer`, `IntakeEvidence`, `FeedbackLoop`, `Hypothesis`, `DiagnosisEvidence` (registered in the `Evidence` union); `IntakePhaseConfig` / `DiagnosisPhaseConfig` on `AutodevConfig` (default enabled); agent-model + denylist entries for the 3 new roles; budget bumps (reviewer 5→8, critic_t/synthesizer 1→6).
- **Phase 1 — Execute-layer fixes (A1–A4): landed.** A1 reviewer turn-exhaustion soft-pass; A2 `depends_on` emission + inference + plan-gate warning; A3 `abort_failed_apply` merge-rollback; A4 text-only tournament roles drop `Read`.
- **Phase 1 — Intake (ADR-0045): landed.** `run_intake_phase` (assess→gather→enrich→clarify→lock), `intake_sources/` plugin gather (repo/github/jira/sessions), `spec_validator.assess`, `intake_enricher`/`intake_clarifier` prompts, `autodev intake` + `--no-intake`/`--assume-defaults`.
- **Phase 1 — Diagnosis (ADR-0046): landed.** `run_diagnosis_phase` (sandbox-ordered loop → reproduce → ranked hypotheses → confirmed cause → seam verdict), `diagnostician` prompt, `reproduce_gate` + `debug_tag_gate`, developer/test_engineer regression-first folds.
- **Phase 2 — Integration: landed.** Intake + diagnosis wired into `run_plan_phase` (enriched spec rebinds `intent`/`spec_hash` downstream); diagnosis seam signal threads into framing additively; QA gates wired into `_run_qa_gates`.
- **Phase 3 — Verify: landed.** Full suite **3755 passed / 6 skipped / 0 failed**; 9 fixed failures were all phase-presence/baseline shifts (no production regressions); no new ruff/mypy errors.
- **Phase 4 — Release: landed.** CHANGELOG, this retrospective, `preflight_v041` (25 anchors), ADRs 0045/0046 Proposed→Accepted, version bump, PyPI publish.

## 4. What's NEW

Failure modes introduced or surfaced by this release itself (not on the prior retrospective's list):

- **Caused by the fixes (contained):** intake on-by-default rebinds `spec_hash` to the enriched-spec hash, which moved tournament-salvage directories in 3 unit tests (pre-seeded under the raw-intent hash). Contained by scoping intake off in those isolation tests; flagged below as a field risk.
- **Below the prior layer (now exposed):** with delivery fixed, the binding constraint shifts to *gather quality* (intake) and *loop fidelity* (diagnosis) — both depend on inputs (network, live repro) the autonomous sandbox lacks. The intelligence layer can now be starved by thin gather rather than by symptom-anchored intake.
- **Cross-file contention learned:** two parallel fan-out agents both registered ledger ops in `state/ledger.py` (a file neither formally owned). The edits composed cleanly only because the framing precedent gave an unambiguous insertion point; this was luck, not design. Process note in §6.

## 5. What's the NEXT layer of failure?

**REQUIRED.** Candidates that will surface after v0.41.0 ships, as input to v0.42.0 planning.

- **Candidate 1:** Intake gather is thin headlessly. Severity: High. Why we suspect: the #199 win depends on pulling a linked issue via `gh`/network/Jira-MCP, which are skipped in CI/headless (degrades to repo-only); the very thin specs intake is meant to rescue are exactly the ones where repo-only gather adds least. Falsifiable signal: a benchmark re-run where a thin `bug.md` with an unreachable linked issue still produces a spec that fails G1 or does not materially change the framing altitude vs raw intent.
- **Candidate 2:** Diagnosis synthetic-loop ↔ reality gap. Severity: High. Why we suspect: live-only bugs (the Mistral-429 class) get a synthetic/replay loop + a delivered artifact; the reproduce-gate runs the *synthetic* loop, so it can go green post-fix while the real symptom persists. Falsifiable signal: a run where the reproduce-gate passes post-fix but the delivered `scripts/repro/` artifact still reproduces the bug live.
- **Candidate 3:** `spec_hash` churn breaks resume/caching keys. Severity: Medium. Why we suspect: intake rebinds `spec_hash` mid-pipeline; resume, tournament-salvage dirs, and caches key on it — we already saw 3 salvage unit tests shift. A crash between explorer and intake-lock, or a mixed raw/enriched hash, could mis-key resume. Falsifiable signal: a resumed real run that re-gathers/re-plans or loses on-disk incumbents because the hash moved.
- **Candidate 4:** Dependency inference misses glob/cross-phase deps. Severity: Medium. Why we suspect: inference is deliberately conservative (same-phase, literal file overlap or explicit id ref; globs ignored), so a real dependency expressed via a glob `Files` entry or across phases still won't serialize. Falsifiable signal: a real plan whose glob-Files task pair races in parallel worktrees and produces the same incoherence F-2 targeted.
- **Candidate 5:** Two-phase cost/latency creep on the common path. Severity: Medium. Why we suspect: every plan now adds an intake enrich call and every bug adds several diagnostician calls. Falsifiable signal: the `invocation_cost` ledger shows a material per-plan spend increase vs v0.40.0 baselines on the benchmark suite.

## 6. Process / discipline notes

- The prior (v0.40.0) retrospective predicted the binding constraint would move to *richer context feeding the classifier* — borne out: this release's intake/diagnosis phases exist precisely to enrich the input, and the new top risks (§5 C1/C2) are now about *input quality*, not the framing decision.
- **Shared-file contention in parallel fan-out:** `state/ledger.py` was edited by two parallel agents because op-registration ownership wasn't pre-assigned. It composed cleanly by luck. Change: when fanning out, pre-assign *every* shared registry file (ledger ops, denylist, unions) to a single owner or to the serial Foundation phase, even when the touch is "just additive."
- The on-by-default determinism shift was anticipated and handled (regenerate where the only change is phase presence; scope phases off in isolation unit tests) — no real regressions masked. Keep this triage discipline explicit in future on-by-default rollouts.
